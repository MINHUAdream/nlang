# n 0.7 Unified Phased IR

**状态：原生纵切已实现，通用化与结构共享待完成**  
**日期：2026-10-01**  
**定位：n 原生编译器的统一 IR 数据模型与分阶段合法性规范**

## 1. 决策摘要

n 0.7 不再把 NIR 和 n-LIR 作为两棵彼此独立、需要完整序列化和重建的 IR
树。它们合并为一个统一的 `nIRModule` 数据模型；语义降低、执行规划和机器
降低仍然是三个有严格不变量的阶段：

```text
.n source
  -> nIR.semantic
  -> nIR.planned
  -> nIR.machine
  -> n-owned machine code
  -> RTM Echo/Commit
```

这里合并的是数据模型、值系统、区域图、效果系统、摘要链和 provenance，不是
把所有语义和机器细节放进一个无约束的节点表。每个阶段有自己的合法操作集合；
阶段转换是同一模块上的受验证重写，或者共享结构的持久化快照。

## 2. 为什么不采用完全单层 IR

删除所有阶段边界不会自动提高最终程序运行性能。它会把 `Goal`、`Contract`、
误差界、RealityTag、设备放置、内存布局、ABI、寄存器和机器指令混在一起，导致：

- 高层语义在早期 lowering 中丢失，无法进行精确回退和 Echo 验证；
- 任意阶段可以制造任意操作，verifier 的规则数量呈组合增长；
- 机器相关细节污染参考解释器和跨后端计划；
- 优化候选难以判断自己是否仍然 refine 了原始契约。

因此 0.7 采用“一个数据模型，三个合法性阶段”，而不是“一个没有阶段的 IR”。

## 3. 统一模块模型

概念接口如下，字段以规范语义为准，具体存储可采用紧凑数组、arena 或持久化
结构共享：

```text
nIRModule {
    schema: "n-ir/0.7",
    phase: IRPhase,
    values: ValueTable,
    types: TypeTable,
    regions: RegionTable,
    operations: OperationTable,
    contracts: ContractTable,
    effects: EffectTable,
    placements: PlacementTable,
    provenance: ProvenanceTable,
    rewrites: RewriteLog,
    source_digest: Digest,
    parent_digest: Digest?,
    module_digest: Digest
}
```

统一的 `Value` 至少可携带：类型、shape、layout、device、numeric contract、
ownership、RealityTag、定义操作和 provenance。调试/审计模式保留完整字段；热
路径可以擦除已由 verifier 证明的字段，但必须保留证明摘要和回退边。

## 4. 三个 IR phase

### 4.1 `semantic`

允许表示：

- Field、Wave、Goal、Synthesize、Transition、Delta、Echo、Commit；
- 类型、shape、所有权、RealityTag、显式效果和数值语义；
- 高层控制流和 region，但不出现物理寄存器、ABI 偏移或目标指令。

必须满足：值有唯一合法定义；shape/类型/效果/现实标签一致；提交边界和回退
语义完整；任何外部效果都显式声明。

### 4.2 `planned`

在不改变语义契约的前提下增加：

- layout、device、memory space、tile、vector width；
- precision/profile、误差预算、通信和同步策略；
- 并行策略、候选 plan、验证器和 fallback edge；
- 已测或待测的 CostVector 引用。

计划阶段可以有多个候选快照。候选只有在 `PlanManifest` 与 workload、硬件、
目标 epoch 和源/NIR 摘要匹配时，才可以进入测量或晋升。

### 4.3 `machine`

只允许已选择目标和 ABI 后的机器相关表示：

- 物理/虚拟寄存器、栈槽、buffer offset、调用约定；
- 目标向量指令、分支、内存访问、屏障和数据移动；
- 机器级错误/回退边以及代码生成所需的证明摘要。

机器 phase 仍保留原始契约引用、计划摘要、精度/误差界和回退目标；不能通过
删除高层字段来伪造“已证明”。`n_codegen_x64.py` 只接受 `machine` phase。

## 5. Phase legality 与 verifier

每个 operation 带有 `min_phase` 和 `legal_phases`。例如：

| Operation | semantic | planned | machine |
| --- | --- | --- | --- |
| `field`, `wave`, `delta`, `commit` | 允许 | 保留/细化 | 只能作为契约引用 |
| `goal`, `synthesize` | 允许 | 规划结果 | 禁止 |
| `tile`, `vectorize`, `place` | 禁止 | 允许 | 已具体化 |
| `buffer`, `move`, `layout_cast` | 契约占位 | 允许 | 允许 |
| `reg`, `stack_slot`, `abi_call` | 禁止 | 禁止 | 允许 |
| `x86.sse2.addpd` | 禁止 | 候选描述 | 允许 |

Verifier 分为四个可组合层：

1. **Structural**：引用、region、拓扑、摘要和 schema；
2. **Semantic**：类型、shape、ownership、effects、RealityTag、CommitGate；
3. **Phase**：当前 phase 的 operation legality 和必需字段；
4. **Target**：ABI、指令约束、能力表、数据布局和硬件特性。

任何一层失败都 fail-closed，返回结构化诊断，不隐式降级为另一阶段或另一后端。

## 6. Rewrite delta 与结构共享

阶段转换不复制整棵 IR。统一模块支持两种等价实现：

```text
semantic snapshot
    + RewriteDelta(layout/vector/effect refinement)
    -> planned snapshot
    + RewriteDelta(buffer/reg/abi lowering)
    -> machine snapshot
```

`RewriteDelta` 必须包含：基线 `parent_digest`、受影响 value/region、旧值摘要、新值
摘要、规则 id、verifier 结果、成本和回退引用。快照可以共享未变化的 arena 节点；
序列化时仍产生完整规范表示，保证跨进程回放不依赖内存地址。

这会降低编译器的对象分配、复制、JSON 摘要和缓存压力，但不改变最终 kernel 的
指令质量。任何“运行更快”的结论仍必须来自目标硬件和绑定 workload 的 receipt。

## 7. PlanManifest 的新定位

`PlanManifest` 不是第三套 IR，也不拥有独立的执行节点图。它是 nIR 上一次候选
选择的不可变证明索引：

```text
PlanManifest {
    source_digest,
    semantic_digest,
    planned_digest,
    target,
    capabilities,
    placement,
    numeric_profile,
    schedule,
    verifier_digest,
    fallback,
    benchmark_manifest,
    objective_epoch
}
```

计划 manifest 必须能重建并验证对应的 `planned`/`machine` 快照；摘要、能力、
shape、效果、数值契约或目标 epoch 不匹配时拒绝执行。声明的 cost/quality 仍然
只是估值；只有绑定相同源、工作负载、硬件、编译器、运行时和基准摘要的实测回执
才可以驱动 `synthesize` 的晋升。

## 8. 编译与运行数据流

```text
.n
  -> parser + semantic verifier
  -> nIR.semantic
  -> candidate planner / goal-synthesize
  -> nIR.planned + PlanManifest
  -> measured admission
  -> nIR.machine
  -> register/ABI/codegen
  -> executable artifact
  -> RTM candidate Delta
  -> exact/contract Echo
  -> atomic Commit
  -> MeasurementReceipt
```

参考解释器消费 `semantic` 或 `planned` 的可解释投影；目标后端消费 `machine`。
后端不能直接读取源代码、旧 tl AST、固定 kernel 名表或未验证的候选指标。

## 9. 性能目标与验收口径

0.7 将两类性能分开验收：

### 编译器性能

测量 IR 节点分配、快照重写、digest/序列化、plan 搜索、验证和缓存命中。目标是
统一模型降低编译延迟、峰值内存和重复摘要工作；必须报告冷启动、稳态和 p99。

### 生成程序性能

测量纯 kernel、数据移动、同步、回退、验证、编译和缓存成本。统一 IR 本身不构成
加速证据；只有在同一 workload、输入、精度、硬件、编译器版本和基准协议下，相对
C/Fortran/tl/Python 的实测才可以报告差异。

最小验收矩阵：

| 项目 | 必须证明 |
| --- | --- |
| phase round-trip | semantic/planned/machine 快照摘要稳定，父摘要链完整 |
| semantic preservation | machine 快照可回指原契约，参考执行与目标执行满足声明容差 |
| legality | 跨 phase 非法 operation 被拒绝，未知字段/重复引用 fail-closed |
| manifest binding | 源、shape、layout、numeric、target、hardware 或 objective 改变会失效 |
| fallback | Echo 失败、能力缺失、漂移或超预算返回旧计划/参考路径 |
| compiler cost | 节点数、重写数、序列化和验证成本都有可重放 receipt |
| runtime cost | p50/p99、质量损失、搜索次数、回退率和数据移动成本分开记录 |

## 10. 从当前实现迁移

当前 `n_ir.py` 的 `NIRModule` 已承载 0.7 三阶段数据；`n_lir.py` 的 `LIRKernel`
保留为 0.50 兼容投影。迁移结果：

1. `IRPhase`、统一 operation/value/region 表和 phase verifier 已实现；
2. 旧 NIR 可映射为 `semantic`，旧 canonical digest 保存为 `legacy_digest`；
3. `PlanManifest v2` 保持模块外不可变索引，planned 决策写入模块 operation 和
   `RewriteDelta`，从而避免 manifest/模块摘要循环；
4. buffer/effect/loop/numeric contract 已进入 machine 表，`n_codegen_x64.py` 的新
   权威入口校验 `phase == machine`；
5. `LIRKernel` 已降为只读兼容投影，新 x64 路径直接接收 machine snapshot；
6. 新旧入口差分已通过，但兼容 API 暂不删除，等待更多 operation/backend 覆盖。

当前实现没有物理 arena 结构共享：规范化 snapshot 仍会复制映射。该性能优化和
0.50/0.7 编译成本对照属于下一实施阶段，不能由统一 API 本身推断完成。

迁移过程中不得改变 `.n` 的 RTM Echo/Commit 语义，也不得删除旧 tl 回归资产。旧
tl v0.7（增量训练）和原 n-0.7（MemoryStore/多螺旋）是历史编号；本方案正式名
为 **n 0.7 Unified Phased IR**，不覆盖它们。

## 11. 不在 0.7 的内容

本版本不宣称已经实现：通用 CFG/SSA、完整寄存器分配、目标文件/链接器、自举、
GPU tile、NPU SRAM、CXL executor、跨设备真实测量或自动 measured-goal 晋升。它们
可以复用统一 nIR，但必须各自增加 phase legality、能力、回退和真实 workload 证据。

## 12. 失败策略

- phase 不合法：编译拒绝；
- manifest 过期或摘要不匹配：拒绝执行；
- 目标能力缺失：返回 `unavailable`，不写零成本；
- Echo 失败或误差超界：不提交，走 reference/旧计划；
- 统计样本不足：标记 `unknown` 或置信区间不足，不生成泛化性能结论；
- 迁移失败：保留 0.50 NIR/LIR 路径和旧 tl 兼容路径。

统一 IR 的目的，是减少不必要的中间对象并让契约贯穿到机器码；不是用架构口号
替代测量，也不是以牺牲可验证性换取“少一层”的表面简化。
