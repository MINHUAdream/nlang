# n 0.8-A Measured Goal and CPU SIMD Design

## Status

Accepted for implementation on the `n-0.8-measured-goal-simd` branch. This
increment extends the verified n 0.7 native slice; it does not widen the
language to GPU, NPU, CXL, general SSA/CFG, or self-hosting.

## Goal

Make `goal`/`synthesize` part of the executable n compilation path for one
workload family: contiguous CPU `f64 add_scalar` waves on Windows x86-64. The
planner must enumerate explicit candidates, measure the same workload, select
only a candidate whose exact Echo passes, and preserve an exact reference
fallback when native execution is unavailable or rejected.

## Non-goals

- No CUDA, ROCm, NPU SRAM, CXL memory, or neuromorphic executor.
- No claim that a candidate is faster than C, Fortran, vendor libraries, or a
  different workload unless the receipt binds that comparison.
- No implicit LLM, tokenizer, prompt, model-weight, or service dependency.
- No mutable plan metadata embedded in a phase digest.
- No broad optimizer or general control-flow lowering.

## Core Model

The authoritative path remains:

```text
.n source
  -> semantic nIR (goal + synthesize are explicit operations)
  -> planned nIR (candidate set + measured selection)
  -> machine nIR (one selected backend)
  -> n-owned machine bytes
```

`PlanManifest` remains an immutable external index. It binds source, semantic,
planned, machine, objective epoch, candidate-set digest, selected candidate,
measurement receipt, and fallback. It never stores mutable plan state inside
the module that it digests.

### Candidate

```python
CandidateSpec(
    name: str,
    backend: str,
    required_features: tuple[str, ...],
    operation: str,
    numeric_contract: str,
    fallback: str,
)
```

The first candidate set is deterministic and fixed:

1. `reference_exact` using `ReferenceBackend`.
2. `cpu_simd_sse2` using the existing two-lane SSE2 executor.

The selected candidate must be one of the declared candidates. Candidate order
is canonicalized by name; ties resolve lexicographically by candidate name.

### Measurement

Each available candidate runs the same immutable source, field snapshot,
sample count, warmup count, and benchmark binding. The receipt records:

- candidate-set digest and selected candidate;
- search count and unavailable/infeasible candidates;
- compile, initialization, execution p50/p99, and exact Echo verification cost;
- quality loss, fallback count/rate, commit count;
- source, semantic/planned/machine, compiler, runtime, backend, hardware,
  workload, benchmark, and result digests.

Unknown cost is `None`, never zero. A candidate that cannot be probed or whose
Echo fails is not selected. If all accelerated candidates are unavailable, the
reference candidate remains the semantic fallback and the receipt reports the
unavailability explicitly.

The default selection policy is `adaptive-fastest` within the declared
candidate set, subject to `quality_loss <= 0` for this exact operation. The
reference candidate is always eligible and provides the deterministic tie and
failure floor.

## n-Owned Machine Encoding

The native x86-64 encoder moves to `n_machine_encoder_x64.py`. It contains only
the minimal instruction builder required by this slice and has no dependency on
the legacy tl parser, AST, VM, or emitter module. `tl_emit.py` remains an
untouched compatibility artifact for the historical tl path. The n codegen
module imports the n-owned encoder only.

The emitted kernel remains Windows x64 ABI compatible and retains W^X loading,
instruction-cache flush, exact Echo, and RTM commit gating from 0.7.

## Phase and Failure Rules

- Semantic modules may contain `goal` and `synthesize`, but no machine backend
  operation.
- Planned modules must contain exactly one canonical candidate-set operation and
  one selection operation; their parent digest must be the semantic digest.
- Machine modules contain exactly one selected backend operation and must bind to
  the planned digest.
- A stale objective epoch, source digest, candidate-set digest, hardware digest,
  or workload digest rejects execution.
- Failed measurement, unavailable capability, failed Echo, and error-budget
  overflow leave the field uncommitted and retain the reference/previous plan.
- The planner never silently turns an unavailable device into a zero-cost option.

## Compatibility

`compile_source` continues to compile the existing no-goal `rtm_add_one.n`
through the same 0.7 path. `compile_source_legacy`, `LIRKernel`, and the
historical tl entry points remain available for differential tests. Goal-bearing
sources gain a new measured path without changing the old nIR/RTM schema.

## Acceptance Evidence

The increment is accepted only when:

1. a goal-bearing `.n` source parses and lowers to semantic nIR;
2. planning emits a digest-linked planned snapshot and a deterministic
   selection receipt;
3. the selected CPU SIMD candidate executes and passes exact Echo on supported
   Windows x86-64 hosts;
4. unavailable hosts produce explicit `unavailable` or reference results with
   unknown latency fields, never fabricated zeros;
5. machine bytes from the n-owned encoder match repeated compilation and the
   old 0.7 supported workload remains byte-for-byte stable;
6. the full n test suite passes twice and receipts bind the measured workload.
