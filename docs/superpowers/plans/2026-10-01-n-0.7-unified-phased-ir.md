# n 0.7 Unified Phased IR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the independent NIR/LIR object boundary with one phase-checked `NIRModule` while preserving semantic contracts, digest lineage, native lowering, RTM commit semantics, and the 0.50 compatibility path.

**Architecture:** Python uses the existing public name `NIRModule`; schema `n-ir/0.7` makes it the authoritative unified IR container. `semantic`, `planned`, and `machine` snapshots are connected by verified `RewriteDelta` values. `PlanManifest` indexes the selected snapshots and evidence instead of duplicating operations, while `LIRKernel` remains a read-only compatibility projection until differential tests pass.

**Tech Stack:** Python 3.14 transitional host, `unittest`, canonical JSON/SHA-256, existing n parser/RTM/native x86-64 emitter. No LLVM/MLIR dependency and no legacy tl AST in the `.n` path.

**Spec:** `docs/superpowers/specs/2026-10-01-n-0.7-unified-phased-ir-design.md`

## Global Constraints

- `NIRModule` with schema `n-ir/0.7` is the authoritative new IR; schema `n-ir/rtm-0.1` and `LIRKernel` remain compatibility inputs during migration.
- Every phase transition preserves source digest, semantic contract, effects, numeric contract, fallback, and provenance lineage.
- `n_codegen_x64.py` accepts only a verified `machine` snapshot on the new path.
- Unknown capability, unknown cost, insufficient samples, and stale manifests fail closed; none become zero.
- Existing RTM Echo/Commit behavior and old tl regression assets remain unchanged.
- No task may delete the 0.50 path before Task 6 differential and rollback tests pass.
