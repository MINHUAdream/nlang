# n Native Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile the supported n `f64 add_scalar` program through NIR and a validated plan into executable Windows x86-64 code, then verify and measure it through RTM.

**Architecture:** `n_compile.py` orchestrates parse, NIR, manifest validation, typed n-LIR, and code generation. `n_plan.py` defines the digest-bound plan contract; `n_lir.py` makes buffers/effects/loops/numeric contracts explicit; `n_codegen_x64.py` lowers the supported LIR operation to n-owned machine bytes; `n_native.py` executes those bytes. `n_measure.py` times compile, backend initialization, execution, exact verification, and commit separately.

**Tech Stack:** Python 3.14 transitional host, `unittest`, ctypes, Windows x86-64/SSE2, n-owned x86-64 encoder. No LLVM, C compiler, external assembler, or legacy tl parser/AST is used in the n execution path.

**Spec:** `docs/superpowers/specs/2026-10-01-n-unified-compiler-design.md`

## Global Constraints

- The first native slice supports contiguous CPU `f64` `add_scalar` waves on Windows x86-64/SSE2.
- NIR is the backend input; legacy tl parser/AST/VM are not used for `.n` compilation.
- A backend candidate must pass exact Echo before RTM commit.
- Unsupported or unavailable capability is explicit and must not produce zero-cost measurements.
- Performance statements are limited to the exact workload, host, and sample count in the receipt.
- Historical tl regression files and generated bootstrap artifacts are preserved.
