# n 0.8-A Measured Goal and CPU SIMD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect goal/synthesize to executable planned nIR and measured CPU SIMD selection for the supported `f64 add_scalar` workload, with exact fallback and n-owned x86-64 encoding.

**Architecture:** Keep the 0.7 semantic -> planned -> machine chain. Add a canonical candidate-set and selection operation to the planned phase, bind its digest and receipt through `PlanManifest`, and lower only the selected candidate to machine nIR. Extract the minimal x86-64 encoder used by n into `n_machine_encoder_x64.py`; tl remains a compatibility path, not an n backend dependency.

**Tech Stack:** Python 3.14 transitional host, `unittest`, ctypes, Windows x86-64/SSE2, canonical JSON/SHA-256. No LLVM, CUDA, ROCm, NPU SDK, CXL provider, or LLM dependency.

**Spec:** `docs/superpowers/specs/2026-10-02-n-0.8-measured-goal-simd-design.md`

## Global Constraints

- Only contiguous CPU `f64 add_scalar` waves are executable in this increment.
- `goal` and `synthesize` remain explicit semantic nIR operations.
- Planned selection is deterministic, measured, digest-bound, and fail-closed.
- `reference_exact` is always the semantic fallback; unavailable candidates never receive zero cost.
- n codegen cannot import `tl_emit.py`; historical tl files remain compatibility artifacts.
- Existing 0.7 no-goal compilation, legacy LIR projection, RTM Echo/Commit behavior, and machine bytes remain unchanged.
- GPU/NPU/CXL capability probes remain explicit and no executor is added here.
